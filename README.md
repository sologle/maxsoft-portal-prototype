# MaxSoft Portal — кликабельный прототип этапа 1

Интерактивный прототип закрытого B2B-портала MaxSoft: база знаний, поиск по статьям и вложенным файлам, компании и пользователи, администрирование. Соответствует макетам этапа 1 (24 экранные группы, desktop 1440 px и mobile 390 px).

**Это только фронтенд-прототип на мок-данных**: данные не сохраняются, бэкенд не подключён. Назначение — демонстрация и утверждение пользовательских флоу заказчиком.

▶ **Демо:** https://sologle.github.io/maxsoft-portal-prototype/

## Как смотреть прототип

1. Откройте ссылку — вы на гостевой главной. Кнопка **«ДЕМО»** (справа внизу) — служебная панель прототипа: переключение роли и формата без повторного входа.
2. Роль выбирается при входе: на экране «Вход» под формой есть демо-чипы быстрого входа для каждой роли. Любые введённые email/пароль тоже работают.
3. Формат: на широком экране открывается desktop-версия (1440), на телефоне — мобильная (390). Переключать формат можно кнопкой «ДЕМО» или простым изменением ширины окна. Переходы внутри продукта всегда остаются в своём формате.

### Роли и что смотреть

| Роль | Маршрут |
|---|---|
| **Гость** | Главная → вход / регистрация (3 сценария) / восстановление пароля; закрытая ссылка → вход → возврат к статье |
| **Администратор портала** | Компании → карточка компании → типы компаний → пользователи портала (приглашение, смена роли, удаление) → администрирование (интеграции, журнал действий, поля компании) → база знаний (структура, теги, файлы) → создание и публикация статьи |
| **Инженер ТП / автор** | Редактор статьи → импорт DOCX (процесс/успех/ошибка) → панель статьи → публикация; компании и пользователи (без смены ролей); попытка открыть «Администрирование» → отказ в доступе |
| **Менеджер** | staff-версия базы знаний на просмотр, компании и пользователи (без смены ролей и удаления), выбор типа компании |
| **Администратор клиента** | доступная базе знаний, поиск, пользователи только своей компании (приглашение, блокировка/разблокировка), закрытые материалы → отказ в доступе |
| **Сотрудник клиента** | база знаний, поиск, статьи и видео с таймкодами; закрытые материалы → отказ в доступе |

### Демо-сценарии регистрации

- email на `@sibirproject.ru` (или другой известный домен) + пустой/совпадающий ИНН → **привязка к существующей компании**;
- новый домен + новый ИНН → **создание новой компании** (регистрант становится её администратором);
- известный домен + чужой ИНН (например `7701234567`) → **ручная проверка** без доступа.

### Заглушки

Не реализуемое в прототипе (отправка писем, реальная загрузка файлов, сохранение данных, видео, Helpdesk и ИИ-помощник следующих этапов) закрыто правдоподобными заглушками: диалоги, уведомления, статусы процесса. Helpdesk и ИИ-помощник показаны только как отключённые плитки «Скоро на портале».

## Запуск локально

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # прод-сборка в dist/
```

Стек: React 19 + TypeScript + Vite + Tailwind CSS 4, иконки Lucide. Роутинг — хэшовый (react-router), работает на статическом хостинге без серверных настроек.
